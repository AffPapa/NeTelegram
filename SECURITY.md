# Security policy / Политика безопасности

## Supported versions / Поддерживаемые версии

There is no stable public release yet. Security fixes are developed against the current source tree; no release support window is promised until a signed release exists.

Публичного стабильного релиза пока нет. Исправления готовятся для текущего исходника; сроки поддержки релизов будут опубликованы после появления подписанной сборки.

## Reporting a vulnerability / Сообщение об уязвимости

Do not post exploit details, private account data, or credentials in a public issue. Use GitHub's private vulnerability reporting for the repository when it becomes available. Until then, contact the project owner through a private channel already known to you; do not send Telegram session data or account databases.

Не публикуйте в открытом issue детали эксплуатации, личные данные аккаунтов или секреты. После включения репозитория используйте GitHub Private Vulnerability Reporting. До этого сообщите владельцу проекта приватным способом, который уже известен вам; не отправляйте Telegram-сессии и базы аккаунтов.

Never attach phone numbers, OTPs, 2FA passwords, API hashes, Keychain exports, TDLib databases/files, signing certificates, update keys, or raw logs that may contain account identifiers. Share only a minimal sanitized reproduction.

Не прикладывайте номера телефонов, OTP, пароли 2FA, API hash, выгрузки Keychain, базы/файлы TDLib, сертификаты подписи, ключи обновления или необработанные логи с идентификаторами аккаунтов. Передавайте только минимальный очищенный пример.
